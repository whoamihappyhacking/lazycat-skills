# 独立鉴权（`public_path`）

`application.public_path` 只关闭指定 HTTP 路径的微服账号密码强制鉴权。它不等于公网匿名访问：当前仍需先登录微服客户端并建立虚拟网络。

官方原文：<https://developer.lazycat.cloud/advanced-public-api.html>

## 默认策略

**默认不配置 `public_path`。** 只有应用确实提供 webhook、带签名下载或自有鉴权接口时，才放行完成威胁评估的最窄路径：

```yaml
application:
  public_path:
    - /webhooks/provider
```

对应后端仍须校验消息签名、时效、nonce/重放或应用自己的等价凭据。不要放行管理接口、调试接口、任意文件读取接口，也不要为了省事开放根路径 `/`。

## 身份 Header 行为

`public_path` 上 Ingress 仍尝试鉴权：

- 成功：应用仍收到平台生成的身份 Header。
- 失败：平台清空相关 `X-HC-*` Header，但不拦截请求。

因此应用必须显式判断 `X-HC-User-ID` 是否存在；未登录请求不能继承默认用户或管理员身份。

## 排除语法

官方支持以 `!` 开头的排除项，排除优先级最高且不支持嵌套判断。YAML 中应把含 `!` 的值加引号，避免被解析成 YAML tag。此语法常与大范围放行组合，容易漏出新路由；除非经过完整路由审计，不要采用“开放全部再排除少数”的策略。

## 审核清单

- 逐条说明为什么不能使用默认平台鉴权。
- 匹配范围已按目标版本官方语义验证，没有误把某路径当通配前缀。
- 未登录、已登录、伪造 `X-HC-*`、签名错误、签名重放都已测试。
- 新增路由不会意外落入放行范围。
- 日志不记录 URL Token、签名密钥或其他敏感凭据。
